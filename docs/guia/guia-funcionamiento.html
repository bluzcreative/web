01 · El mapaBluz Creative

Cinco piezas, cada una con un solo trabajo.

La web es un sitio estático: rápido, seguro y barato. No tiene panel de administración propio; el contenido que cambia seguido vive en Notion y los correos viven en Kit.

GitHubGuarda el código de la web (repositorio bluzcreative/web). Cada cambio de diseño pasa por aquí.
NetlifyConstruye y publica la web. Recibe los formularios. Aquí se conecta el dominio.
NotionBase "Bluz Lab" en Bap's board: artículos, descargables, experimentos y ediciones de Contraluz.
MakeCuenta de Bluz (bluzcreative@gmail.com). Une las piezas: avisa a Netlify y pasa correos a Kit.
KitLista de suscriptores, envío de descargables por correo y newsletter Contraluz.
GoDaddyDonde está registrado bluzcreative.com. Solo se toca para apuntar el dominio a Netlify.

Lo que pasa en cada caso

Notion→Make→Netlify reconstruyeMarcas "Actualizar web" y en unos minutos la entrada está publicada.
Formulario de contacto→Netlify Forms→Tu correoCada mensaje te llega por email y queda guardado.
Contraluz→Netlify Forms→Make→KitQueda suscrito a la newsletter.
Descargable→Netlify Forms→Make→KitRecibe el archivo por correo y queda suscrito.
Cambio de diseño→GitHub→Netlify reconstruyeLo hacemos nosotras con el código, como hasta ahora.
Por qué así: nadie toca código para publicar contenido, los correos quedan en una herramienta hecha para enviarlos, y la web solo se reconstruye cuando de verdad hay algo nuevo, que es lo que gasta créditos en Netlify.

02 · Netlify y el planBluz Creative

Hoy alcanza el plan gratis. Para el lanzamiento, Personal.

Netlify cobra en créditos. Cada mes trae una cantidad y cada acción gasta una parte. Si se acaban en el plan gratis, la web se pausa hasta el mes siguiente.

PlanPrecioCréditos al mesPara qué alcanza
Free0 USD300Etapa de revisión: pocos deploys y pocas visitas.
Personal9 USD1.000La web publicada con el dominio, publicaciones semanales y tráfico normal de agencia.
Pro20 USD3.000Solo si las campañas traen mucho tráfico o se suman más personas al equipo.
Qué gasta créditosCuántoEn la práctica
Publicar (deploy)15Cada vez que la web se reconstruye: un cambio de diseño o un "Actualizar web" desde Notion.
Tráfico (bandwidth)20 por GBLo que más pesa son los videos de los proyectos. Una visita que mira varios proyectos puede descargar entre 20 y 40 MB.
Visitas (requests)2 por cada 10.000Casi nada.

Mi recomendación

  • Ahora: seguir en Free. Este mes llevamos 0 de 300 créditos y la web ya está publicada en bluz-web.netlify.app (con acceso solo para el equipo).
  • El día que conectemos bluzcreative.com: pasar a Personal (9 USD al mes). Con 1.000 créditos caben unos 20 deploys al mes y unos 35 GB de tráfico, que son entre 1.000 y 1.500 visitas que miran videos.
  • Si una campaña dispara las visitas: Netlify avisa por correo al acercarse al límite. Se puede comprar un paquete de créditos sin cambiar de plan.
  • Para gastar menos: publicar las entradas de Notion juntas (una sola actualización por tanda) y no subir videos más pesados de lo necesario.
Acceso restringido: hoy la web en Netlify solo la ven las personas con sesión en el equipo de Netlify. Eso se quita el día del lanzamiento (Configuración del proyecto → Access & security → Visitor access).

03 · Publicar en Bluz Lab con NotionBluz Creative

Escribes en Notion, marcas dos casillas y listo.

Cada fila de la base "Bluz Lab" es una entrada. Lo que escribes dentro de la página (títulos, párrafos, listas, citas, imágenes) se convierte en el artículo.

Campo en NotionTipoPara qué sirve
TítuloTítuloEl título de la entrada.
TipoSelecciónArtículo, Descargable, Experimento o Contraluz. Define en qué sección aparece.
IdiomaSelecciónES o EN. Cada idioma es una fila distinta.
ResumenTextoUna o dos líneas: aparece en el listado y en Google.
FechaFechaFecha de publicación. Ordena el listado.
PublicadoCasillaMarcada: la entrada está en la web. Desmarcada: no aparece.
Actualizar webCasillaEl botón de publicar. Al marcarla, Make reconstruye la web y la desmarca sola.
PortadaArchivoOpcional. Imagen de cabecera.
ArchivoArchivoSolo descargables: el PDF o un enlace (Drive, Canva).
SlugTextoOpcional. La dirección de la página. Si lo dejas vacío se arma con el título.
TraducciónTextoOpcional. Una palabra igual en la versión ES y EN para unirlas (ej. guia-meta-ads).
EdiciónNúmeroSolo Contraluz: número de la edición.
EtiquetasSelección múltipleOpcional, para ordenar.

Publicar una entrada

  1. Crea una fila nueva y escribe dentro de la página.
  2. Completa Tipo, Idioma, Resumen y Fecha.
  3. Marca Publicado.
  4. Marca Actualizar web. En 2 a 5 minutos está en línea.

Corregir o quitar

  1. Corregir: edita la página y marca Actualizar web.
  2. Quitar de la web: desmarca Publicado y marca Actualizar web. Queda guardada en Notion.
  3. Si borras la fila: también desaparece de la web, en la siguiente actualización.
Imágenes y archivos: los que subes a Notion se copian a la web al publicar, porque los enlaces de Notion caducan en una hora. Usa imágenes de hasta 2 MB para que la página cargue rápido.

04 · Configuración única: Notion y MakeBluz Creative

Se hace una sola vez.

A. Darle a la web permiso para leer Notion

  1. Entra a notion.so/profile/integrations con la cuenta del workspace donde está Bap's board y crea una integración interna llamada Bluz Web, con permiso solo de lectura.
  2. Copia el token secreto que te muestra (empieza con ntn_).
  3. Abre la base Bluz Lab en Notion → menú ••• → Conexiones → agrega Bluz Web.
  4. Copia el id de la base: es la parte larga de la dirección de la base, antes del ?v=.
  5. En Netlify: proyecto bluz-web → Project configuration → Environment variables. Crea NOTION_TOKEN con el token y NOTION_LAB_DB con el id. Son privadas: no quedan en el código.

B. El aviso de publicar (escenario en Make)

  1. En Netlify: Project configuration → Build & deploy → Build hooks → Add build hook, nombre "Notion", rama de producción. Copia la URL.
  2. En Make (cuenta de Bluz), escenario nuevo "Bluz Lab · Actualizar web":
    • Notion · Watch Database Items sobre Bluz Lab, cada 15 minutos.
    • Filtro: Actualizar web = sí.
    • HTTP · Make a request: método POST a la URL del build hook.
    • Notion · Update a Database Item: desmarca Actualizar web en esa fila.
  3. Activa el escenario. Para probar, marca Actualizar web en una entrada de prueba y mira en Netlify → Deploys que aparezca una nueva publicación.
Por qué una casilla y no automático al editar: Notion guarda cada letra que escribes. Si cada edición reconstruyera la web, una tarde de correcciones gastaría todos los créditos del mes. La casilla te deja decidir cuándo publicar.
Requisito: el build hook solo existe cuando Netlify construye la web desde GitHub. Por eso primero hay que subir el código a GitHub y conectar el repositorio (sección 07).

05 · Correos con KitBluz Creative

Cada correo llega a su lugar.

FormularioDónde quedaQué pasa después
ContactoNetlify FormsTe llega un email con el mensaje. No pasa a Kit: es una conversación de venta, no un suscriptor.
ContraluzNetlify Forms y KitQueda suscrito a Contraluz en Kit.
DescargablesNetlify Forms y KitVe el enlace en pantalla, recibe el archivo por correo y queda suscrito a Contraluz.

A. En Kit (plan gratis, hasta 10.000 suscriptores)

  1. Crea la cuenta con bluzcreative@gmail.com.
  2. Crea un formulario Contraluz (no hace falta ponerlo en la web: lo usamos de puerta de entrada).
  3. Por cada descargable, crea un formulario con su nombre y activa el incentive email con el archivo adjunto o el enlace. Kit lo envía solo al confirmar el correo.
  4. Settings → Developer: copia la API key para Make.

B. En Netlify y Make

  1. Make: escenario "Web · Suscriptores a Kit" que empieza con un Custom webhook. Copia su URL.
  2. Netlify → Forms → Form notifications → Outgoing webhook para los formularios contraluz y descargables, con esa URL.
  3. En Make, un router: si el formulario es contraluz, Kit · Add subscriber to form "Contraluz"; si es descargables, al formulario de ese recurso (llega en el campo recurso) y también a "Contraluz".
  4. Netlify → Forms → Form notifications → Email notification del formulario contacto a bluzcreative@gmail.com.
¿Hay que conectar algo más para guardar los correos? No. Netlify guarda todos los envíos (los ves en la pestaña Forms y se pueden exportar a CSV) y Kit guarda la lista de suscriptores. Si más adelante quieren un CRM o una hoja de cálculo, se agrega un paso en el mismo escenario de Make.
Textos legales: la política de privacidad ya nombra a Kit como la herramienta que envía Contraluz y los descargables.

06 · Pasar el dominio de Vercel a NetlifyBluz Creative

El dominio no se mueve: solo cambia a dónde apunta.

bluzcreative.com está registrado en GoDaddy y hoy apunta a Vercel. No hay que transferirlo: se cambian dos registros en GoDaddy para que apunte a Netlify. El dominio no tiene correo configurado (no hay registros MX), así que el cambio no afecta ningún email.

  1. Netlify: proyecto bluz-web → Domain management → Add a domain → bluzcreative.com. Elige www.bluzcreative.com como dominio principal y que el otro redirija a ese.
  2. GoDaddy → Mis productos → bluzcreative.com → Nameservers: deja los servidores de GoDaddy por defecto (ns31 y ns32.domaincontrol.com). Hoy también figuran los de Vercel (ns1 y ns2.vercel-dns.com) y hay que quitarlos.
  3. GoDaddy → DNS: borra los registros A y CNAME que apuntan a Vercel (las IP que empiezan con 216.198.79 o 64.29.17, y cualquier cname.vercel-dns.com).
  4. Crea estos dos registros:
    TipoNombreValorTTL
    A@75.2.60.51 hora
    CNAMEwwwbluz-web.netlify.app1 hora
  5. Espera entre 15 minutos y unas horas. En Netlify, Domain management muestra "Netlify DNS propagated" y luego crea el certificado HTTPS solo. Si no lo hace en un par de horas, ahí mismo hay un botón "Verify DNS configuration".
  6. Vercel: cuando bluzcreative.com ya cargue la web nueva, entra al proyecto viejo → Settings → Domains y quita el dominio. Puedes dejar el proyecto archivado unas semanas por si hace falta volver.
  7. Quitar el acceso restringido en Netlify (Access & security → Visitor access) y publicar una vez más, para que las direcciones de Google y de compartir usen el dominio nuevo.
Las direcciones viejas no se pierden: la web ya tiene redirecciones de las páginas antiguas (las que terminaban en .html) a las nuevas, así que los enlaces viejos y Google siguen funcionando.

07 · GitHub y lanzamientoBluz Creative

Lista para el día del lanzamiento.

Subir el código a GitHub (una vez)

  1. GitHub Desktop → File → Add Local Repository → carpeta Documents/GitHub/bluz web.
  2. Rama rediseno → Push origin. Sube todo el trabajo del rediseño.
  3. En GitHub, abre un Pull Request de rediseno a main y únelo (Merge). Así main pasa a ser la web nueva.
  4. Netlify → proyecto bluz-web → Project configuration → Build & deploy → Link repository → GitHub → bluzcreative/web, rama main. El comando y la carpeta ya están en el archivo netlify.toml.

Antes de abrir la web al público

  • Plan Personal activo en Netlify.
  • Variables en Netlify: NOTION_TOKEN, NOTION_LAB_DB y, para medir, PUBLIC_GA_ID (Google Analytics) y PUBLIC_META_PIXEL_ID (Meta). La analítica solo se carga si la persona acepta cookies.
  • Dominio apuntando a Netlify y con HTTPS.
  • Escenarios de Make activos: "Bluz Lab · Actualizar web" y "Web · Suscriptores a Kit".
  • Notificación por email del formulario de contacto.
  • Revisar los textos legales (privacidad, términos y cookies) y los datos de Nosotros, que son borradores.
  • Quitar el acceso restringido y hacer una prueba completa: enviar el formulario de contacto, suscribirse a Contraluz y bajar un descargable.

Qué no cambia

Los proyectos, servicios y textos de la web siguen en el código. Para cambiarlos me escribes y lo hacemos juntas, como hasta ahora; al subirlo a GitHub, Netlify publica solo.
